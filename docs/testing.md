# 테스트 안내

Vimbird의 테스트는 세 층으로 나뉩니다.

| 층 | 대상 | Thunderbird 필요 | 실행 |
|---|---|---|---|
| 단위 | `src/core`, `src/dom`의 순수 로직 | ✗ | `npm test` |
| E2E (자동) | 실제 chrome DOM + 실제 키 이벤트 | ✓ (헤드리스 자동 실행) | `npm run test:e2e` |
| 수동 | 사람 눈·OS 포커스가 필요한 항목 | ✓ | 아래 체크리스트 |

---

## 1. 단위 테스트

```bash
npm test
```

의존성이 없고 Thunderbird도 필요 없습니다. DOM 접근이 필요한 로직(`visibility.js`)은 `{ rect, style, viewport, elementFromPoint }` 어댑터를 주입받도록 설계되어 있어 페이크로 검증합니다.

검증 항목: 라벨 개수·유일성·**prefix-free**·길이 균형·문자셋 변경, 입력 매칭(부분/정확/불일치/삭제), 화면 좌표 정렬, 텍스트 입력 판정, 가시성 판정(0 크기·뷰포트 밖·`display:none`·XUL `hidden`/`collapsed`·가림·부분 노출).

---

## 2. E2E 테스트 (자동)

```bash
npm run test:e2e                       # 소스 디렉터리를 임시 설치해 검증
python3 test/e2e/run_e2e.py --xpi      # 패키징된 XPI로 검증 (npm run build 선행)
python3 test/e2e/run_e2e.py --keep     # 검증 후 Thunderbird를 띄워 둔 채 종료
```

동작 방식: 일회용 프로필을 만들어 헤드리스 Thunderbird를 띄우고(화면이 없으면 `xvfb-run`), Local Folders에 테스트 폴더 2개와 메일 3통을 심고, 확장을 임시 설치한 뒤 **실제 키 이벤트**를 보내 chrome DOM을 검사합니다. 사용자의 실제 프로필은 건드리지 않습니다.

필요 사항: `python3`, 화면이 없을 때 `xvfb-run`. 이미 Thunderbird가 실행 중이어도 별도 프로필 + `-no-remote`로 격리 실행합니다.

현재 12개 시나리오가 아래 수동 체크리스트의 대부분을 자동으로 덮습니다. 실패 시 로그 위치가 실행 첫 줄에 출력됩니다.

---

## 3. 수동 테스트 체크리스트

자동 테스트가 닿지 않는 것: 힌트가 **눈에 보이는 위치에 제대로 그려지는지**, OS 창 포커스가 실제로 바뀌는 상황, 사용자의 실제 계정·대량 메일함에서의 동작.

준비: [`README.md`](../README.md)의 임시 설치 절차로 확장을 로드합니다.

| # | 시나리오 | 조작 | 기대 결과 | 자동화 |
|---|---|---|---|---|
| 1 | 시작 | Thunderbird 실행 후 확장 로드 | 오류 없음, 브라우저 도구 상자 콘솔에 `Vimbird ready` | 간접 |
| 2 | Inbox에서 `f` | 받은 편지함 선택 후 `f` | 툴바·폴더·메일 목록 위에 힌트가 뜬다 | ✓ |
| 3 | 툴바 버튼 힌트 | `f` | 통합 툴바 버튼마다 힌트가 버튼 좌상단에 겹쳐 보인다 | 부분 |
| 4 | 힌트 입력 | 힌트 문자 입력 | 다른 힌트는 사라지고 입력한 글자가 흐리게 표시된다 | ✓ |
| 5 | 실제 동작 | 완성된 힌트 입력 | 해당 버튼이 실제로 눌린다 | ✓ |
| 6 | `Esc` | 힌트 표시 중 `Esc` | 힌트가 모두 사라지고 아무 일도 일어나지 않는다 | ✓ |
| 7 | 다른 폴더 | 폴더 변경 후 `f` | 새 폴더 기준으로 힌트가 다시 계산된다 | ✓ |
| 8 | 메일 선택 상태 | 메일 한 통 선택 후 `f` | 메시지 헤더 버튼(회신/전달/보관)에도 힌트가 뜬다 | ✓ |
| 9 | 메일 연 상태 | 메일을 탭/창으로 연 뒤 `f` | 열린 메시지 화면에도 힌트가 뜬다 | 부분 |
| 10 | 작성 창 | 메일 작성 창에서 `f` | 작성 창 툴바에 힌트가 뜬다 (**OS 포커스 필요 — 반드시 수동 확인**) | 합성 이벤트로만 |
| 11 | 텍스트 입력 | 제목/본문/검색창에 커서를 두고 `f` | 힌트가 뜨지 않고 **`f`가 그대로 입력된다** (**수동 확인 권장**) | 합성 이벤트로만 |
| 12 | 창 크기 변경 | 힌트 표시 중 창 크기 변경 | 힌트가 사라진다(잘못된 위치에 남지 않는다) | ✓ (헤드리스에선 합성 이벤트로 대체될 수 있음) |
| 13 | 스크롤 | 힌트 표시 중 스크롤 | 힌트가 사라진다 | ✓ |
| 14 | 여러 글자 힌트 | 후보가 10개 넘는 화면에서 `f` | 두 글자 힌트가 생기고 두 글자를 다 쳐야 실행된다 | ✓ |
| 15 | 동일 prefix | 예: `sa`, `sd`가 동시에 존재 | `s`만 치면 실행되지 않고 후보만 좁혀진다 | ✓ |

### 특히 사람이 봐야 하는 것

- **힌트 위치**: 대상 요소의 좌상단에 겹쳐 보이는가. 화면 가장자리 요소의 힌트가 잘리지 않는가.
- **가독성**: 다크 테마·밝은 테마 양쪽에서 노란 라벨이 읽히는가.
- **성능 체감**: 메일이 수천 통인 폴더에서 `f`가 즉시 반응하는가(스레드 목록은 가상 스크롤이라 화면에 보이는 행만 후보가 됩니다).
- **10·11번**: 헤드리스 환경에는 창 관리자가 없어 OS 포커스를 다른 창으로 옮길 수 없습니다. 자동 테스트는 합성 키 이벤트로 코드 경로만 확인하므로, 이 둘은 실제 사용 환경에서 한 번 더 봐야 합니다.

### 문제가 보일 때

1. **브라우저 도구 상자**(도구 → 개발자 도구 → 브라우저 도구 상자) 콘솔에서 `Vimbird:` 로 시작하는 경고를 확인합니다.
2. 어떤 요소가 후보로 잡히는지 보려면 브라우저 도구 상자 콘솔에서:
   ```js
   // 확장의 백그라운드 콘솔에서
   await messenger.vimbird.dumpCandidates();
   ```
   문서별 후보 개수와 태그 분포가 출력됩니다. 특정 버튼이 힌트를 못 받으면 여기서 누락 여부를 먼저 확인하고, 필요하면 `src/tb/targets.js`의 셀렉터를 조정합니다.
3. 힌트가 아예 안 뜨면 `messenger.vimbird.getStatus()`로 확장이 창에 붙었는지 확인합니다.
